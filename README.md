# 对标法工具 · Benchmarking Worksheet

一个单文件、零依赖的网页工具。把商业分析里的对标法（Benchmarking）拆成 7 个可填写的步骤，帮你在别人的生意里拆出 3–5 个自己能入手的方向，填完自动生成结论和排序。

不是商业课程，也不是创业模板。它只是一个把成熟方法论做成“能填的东西”的小工具。

## 为什么做这个

对标法是商业分析里很常见的一套方法，施乐公司在 1979 年为了搞清楚“为什么打不过日本厂商”而系统化使用，后来被广泛用于竞品分析和标杆管理。方法本身不新，但大部分人听过就过了，没真拿它拆过自己的方向。

这个工具做的是三件事：

1. 把原来偏学术的流程拆成 7 个低门槛的填写步骤
2. 把「多对象横向拆解」变成可操作的表格，而不是凭感觉
3. 填完自动产出多个候选方向、打分排序和一句话定位

方法不是我的，工具是我自己搭的。

## 功能

- **7 步引导式填写**：从圈定范围到最小验证，每一步有「怎么做」「问自己」和填写区
- **多对象对标表**：横向对比头部玩家、新锐黑马、我的预估，每个维度填事实和数字
- **机会提取**：至少拆出 3 个可乘之机，每个机会自动展开成一张方向卡
- **方向组装与打分**：给每个方向填一句话定位，按可行性、匹配度、需求热度三项各 1–5 分打分
- **自动排序**：按综合分自动排序，可手动指定优先验证的方向
- **实时结论**：页面底部自动生成全部候选方向、推荐优先验证项和验证计划，一键复制
- **本地保存**：所有填写内容自动存到浏览器 localStorage，刷新不丢
- **打印友好**：支持直接打印或导出 PDF

## 快速开始

### 方式一：直接打开

下载 `index.html`，双击用浏览器打开即可。不需要安装任何东西。

### 方式二：部署到 GitHub Pages

1. 把 `index.html` 推到仓库根目录
2. 进入仓库 `Settings` → `Pages`
3. Source 选 `Deploy from a branch`，分支选 `main`，目录选 `/ (root)`
4. 保存后等一两分钟，访问 `https://你的用户名.github.io/仓库名/`

### 方式三：本地起服务（可选）

```bash
# Python 3
python -m http.server 8000

# 或 Node
npx serve .
```

然后打开 `http://localhost:8000`。

## 使用流程

| 步骤 | 内容 | 产出 |
|------|------|------|
| 1 | 圈定范围：三个圈找交集 | 一句话锁定范围 |
| 2 | 挑对标对象：头部 / 新锐 / 退出者 | 3–5 个对标样本 |
| 3 | 建对标维度：6 个格子 | 一套可比模板 |
| 4 | 逐项对比：对标表 | 差距和缝隙 |
| 5 | 机会提取 | 至少 3 个机会点 |
| 6 | 方向组装：定位 + 打分 | 每个机会一张方向卡 |
| 7 | 排序与验证 | 优先方向 + 最小验证计划 |

第 5 步和第 6 步是产出多个方向的关键：每个机会点会自动生成一张对应的方向卡，最后按综合分排序。

## 技术说明

- **纯前端**：单文件 HTML，内含 CSS 和 JavaScript，无框架、无构建、无外部依赖
- **数据存储**：`localStorage`，键名 `benchmark_multi_v2`
- **兼容性**：现代浏览器（Chrome / Edge / Safari / Firefox），移动端自适应
- **打印**：`@media print` 已做基础适配

## 关于方法论

对标法（Benchmarking）的常见起点是 1979 年施乐公司应对日本厂商竞争时的实践，核心顺序是：先了解自己的运营，再了解行业领先者，吸收最佳实践，最后获得优势。这个工具只是把这套顺序做成了可填写的表单，不改变方法论本身。

几点使用提醒：

- **对标对象选错了，后面全是空转。** 选一个你够不着也学不了的头部，除了打击自己，没有别的功能。
- **先填第一步。** 如果「我熟悉的」「有人付钱的」「我愿意坚持的」三个圈对不上，停下来想，比硬凑一个方向有用。
- **信息收集比填表更难。** 如果对某个对标对象的客群、渠道、成本说不清，说明你还没真正进入那个场，填出来的东西只能算假设。
